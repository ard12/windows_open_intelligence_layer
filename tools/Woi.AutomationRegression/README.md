# WPF automation lifetime regression

This opt-in native diagnostic exercises the real desktop MainWindow/XAML, view model, worker, collection publications, charts, selection/current cells, paging, family/process scope and CPU stack navigation while an independent UIA client listens for selection events. It adds no packages and writes all runtime/build outputs under the required OutputRoot. The fixture is read-only. It does not run privileged capture.

```powershell
./tools/Woi.AutomationRegression/run.ps1 -Fixture <existing.etl> -OutputRoot J:/Codex/wpf-regression -DotnetPath <dotnet.exe> -PackageCache <existing-package-cache> -Switch false
./tools/Woi.AutomationRegression/run.ps1 -Fixture <existing.etl> -OutputRoot J:/Codex/wpf-regression -DotnetPath <dotnet.exe> -PackageCache <existing-package-cache> -Switch true -NoBuild
./tools/Woi.AutomationRegression/run.ps1 -Fixture <existing.etl> -OutputRoot J:/Codex/wpf-regression -DotnetPath <dotnet.exe> -PackageCache <existing-package-cache> -Switch true -Phase held -NoBuild
```

The ordinary arms retain no provider objects in the harness; held mode deliberately retains providers until detach. Both verify the effective exact-runtime framework switch before creating MainWindow/peers, complete20 navigation cycles, record one-second UI+monitor working-set samples (analysis separate), and track old row weak references/GC and detach/window-close behavior. The runner asserts the packaged desktop runtimeconfig option and preserves the unchanged300MiB sampled UI+monitor threshold. Owned worker identity includes PID and recorded start time; failed/mismatched reads remain null and fail the active monitoring gate. Post-shutdown unknown memory remains null. Run the built Woi.AutomationRegression.exe with --verify-memory-guard and an output JSON path for focused missing-PID/identity-mismatch negative controls. It throws on crash, incomplete run, wrong effective switch or threshold failure. Memory/retention trends and recovery still require review; the script does not automatically declare stable acceptance. A fresh unique output directory avoids stale signals.

The startup option mitigates the demonstrated .NET10.0.13 expired weak-item cell-peer constructor failure. [Official WPF switch source](https://raw.githubusercontent.com/dotnet/wpf/main/src/Microsoft.DotNet.Wpf/src/PresentationFramework/MS/Internal/FrameworkAppContextSwitches.cs) warns that enabling it can reintroduce memory leaks. It applies throughout the desktop process. The original intermittent application race/grid remains unreproduced; an ordinary baseline pass cannot prove a race repair. This diagnostic uses forced GC and one fixture on a shared host and is not a replacement for the failed historical30-minute memory/coverage run, longer soak or independent screen-reader/physical-input acceptance.
