## Source-grounded findings

**Flat summary versus contextual tree.** `CallTree.AddSampleToTreeNode` adds count and metric exclusively to the leaf, then inclusively to each contextual ancestor. `AccumulateSumByID` accumulates flat summaries while tracking frame IDs on the current path: recursive occurrences contribute exclusive values but do not duplicate their inclusive values. Thus A→B→A→C carrying one sample yields flat inclusive A=1, B=1, C=1 and exclusive C=1; the contextual call tree still contains both A positions. Never sum flat inclusive rows to obtain total CPU. [CallTree.cs:353–411](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L353-L411), [CallTree.cs:421–483](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L421-L483).

**Frame identity is display-name based in this reference.** `FindCallee` interns `GetFrameName(frameID, false)` to obtain a canonical frame ID. Consequently equal names can merge even when original code-address IDs differ. ByID is therefore not a raw-address report. WOI should explicitly define its own grouping key, retain address/module evidence for unresolved frames, and normalize keys before claiming reference row parity. [CallTree.cs:1445–1517](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L1445-L1517).

**Caller/callee recursion has two distinct policies.** The three-pane `CallerCalleeNode` splits each sample across its N recursive focus occurrences using 1/N weighting, including fractional counts. Separate `AggregateCallTreeNode.CallerTree`/`CalleeTree` views remove recursive overlap and use the deepest focus occurrence. The guide explicitly gives A→B→C→B→D: focus B has caller C and callee D in those separate tree views. Do not implement one generic caller/callee routine and claim it reproduces both. [CallTree.cs:1766–1881](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L1766-L1881), [CallTree.cs:1936–1961](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L1936-L1961), [guide:3238–3305](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/PerfView/SupportFiles/UsersGuide.htm#L3238-L3305).

**Metric and count are independent.** `StackSourceSample.Count` defaults to 1; `Metric` is a separate float. `TraceEventStackSource` sets its sample metric to the log's sample-profile interval in milliseconds. `CallTree` sums both independently and uses absolute root-inclusive metric as its percentage denominator. WOI already has per-event CPU weighting; it should preserve that model rather than replacing it with sample count or one global interval. Count is still useful when a millisecond weight is unknown. Neither count nor sampled milliseconds is exact wall-clock duration. [Stacks.cs:378–443](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/Stacks.cs#L378-L443), [TraceEventStacks.cs:50–63](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/TraceEventStacks.cs#L50-L63), [CallTree.cs:33–72](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/CallTree.cs#L33-L72).

**Missing captured stacks are not the same as unresolved symbols.** `TraceEventStackSource.GetStack` can synthesize sampled-instruction-pointer or thread pseudo stacks when an event has no captured stack. Caller traversal also inserts thread/process frames and can insert BROKEN markers for questionable top frames. Names without symbols normally become module!?; `ShowUnknownAddresses=true` retains hexadecimal addresses. WOI must not report a synthesized one-frame sampled-IP entry as a captured call stack. Retain separate no-stack counts, unresolved-frame counts and truncation/incomplete-chain limits. [TraceEventStacks.cs:584–640](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/TraceEventStacks.cs#L584-L640), [TraceEventStacks.cs:234–278](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/TraceEventStacks.cs#L234-L278), [TraceEventStacks.cs:317–426](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/TraceEventStacks.cs#L317-L426).

**Filter boundaries and grouping matter to parity.** `FilterStackSource` accepts include/exclude/fold/group patterns before aggregation. Its time filter expands bounds by 0.0006 ms; `TimeMetric` also accepts overlapping time samples and prorates metric at boundaries. This differs from WOI's exact event-time half-open interval. For a comparable reference, filter source events directly with WOI's declared [start,end) scope and use `ScaleToData` without grouping/folding. Do not silently import PerfView time-boundary or folding policy. [FilterStacks.cs:246–267](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/FilterStacks.cs#L246-L267), [FilterStacks.cs:307–401](https://github.com/microsoft/perfview/blob/65026df998f224dbb30be9a211e82c0ae18225c7/src/TraceEvent/Stacks/FilterStacks.cs#L307-L401).

## Smallest complete WOI contract

Implemented a flat frame summary, contextual call tree, separate innermost-focus caller/callee navigation, function/module grouping, and representative source-event navigation. Apply the existing interval and trace-local process lifetime. State that event-display filters do not implicitly alter CPU stack aggregation. Count each selected CPU sample once, credit its captured leaf exclusively, and credit each distinct frame key inclusively once per sample. Preserve both counts and known millisecond weights; report unknown-weight samples separately rather than treating them as zero. A missing captured stack belongs in the explicit `[No captured stack]` accounting bucket, not an invented observed frame; it receives exclusive credit so all selected samples reconcile. An unresolved captured frame stays in the summary with stable captured identity.

Expose the denominator: selected samples, stack-bearing samples, no-stack samples, known-weight totals and unknown-weight count. Exclusive counts including the missing-stack bucket reconcile to all selected samples; exclusive known weights reconcile to all selected known weights. WOI percentages use all selected sample counts, not weighted milliseconds or whole-system utilization. If depth/frame limits truncate input, label that loss and retain it in coverage accounting. Do not claim unavailable callers were observed.

The implemented tree preserves recursive positions; separate caller/callee views focus the deepest occurrence, crediting each sample once. This does not implement PerfView's three-pane fractional-allocation mode. Defer automatic symbol download, arbitrary regex/group/fold language, baseline comparison and new capture profiles. Use existing TraceEvent and evidence coordinates; avoid introducing a second capture or lifetime model.

## Independent reference qualification using installed TraceEvent

The following is the broader reference-validation procedure. The executed subset and its limits are listed in the verification report below; the complete procedure is not claimed as passed. No dependency installation is required: WOI's TraceEvent 3.2.8 XML/API metadata confirms `TraceEvents.Filter(Predicate<TraceEvent>)`, `TraceEventStackSource(TraceEvents)`, `CopyStackSource(StackSourceStacks)`, `CopyStackSource.AddSample` and `CallTree(ScalingPolicyKind)` are present.

1. Open the same immutable ETLX. Filter directly to `SampledProfileTraceData`, the exact time interval, WOI's idle/nonprocess policy and exact lifetime identity. For the native captured-stack comparison, explicitly require a valid native `CallStackIndex`. Track excluded missing-stack events separately.
2. Construct `TraceEventStackSource(filteredEvents) { ShowUnknownAddresses = true }`, then `CallTree(ScalingPolicyKind.ScaleToData) { StackSource = source }`. Compare root-inclusive sample count, sum of non-root exclusive counts, and normalized per-frame inclusive/exclusive counts. Remove synthetic thread/process/BROKEN rows from frame comparison only, without pretending those nodes are captured frames.
3. Default reference metrics use one log interval. If WOI event weights vary, build a `CopyStackSource` backed by the reference source, copy each sample, and set its metric using a separately enumerated event-coordinate-to-weight map before adding it. Do not map by timestamp alone; several CPUs may sample at the same timestamp. Compare known-weight totals with an explicit float tolerance. State that this checks independent aggregation, while the supplied weight values still come from WOI's weighting model.
4. Add a controlled `InternStackSource` test with root-to-leaf stacks A→B→A→C (weight2) and A→D (weight3): flat A inclusive5/exclusive0, B inclusive2/exclusive0, C inclusive2/exclusive2, D inclusive3/exclusive3. Root metric5; sum of flat exclusive metrics5; sum of flat inclusive metrics12 is intentionally not a total. Counts remain integers 2,1,1,1 respectively. Repeat with missing and unresolved stacks and a process/interval boundary.
5. Save source hash, TraceEvent version, selected event IDs, normalization rules and comparison output. Agreement with the installed library is a qualified independent aggregation check, not a visual PerfView/WPA comparison or proof of capture completeness.

Executed verification uses the installed PerfView/TraceEvent aggregation library, controlled recursive stacks, raw ETLX stack presence, two real fixtures and the native WOI desktop. Remaining risk: no aggregate can recover uncaptured stacks or establish scheduling/wait causes from sampled CPU alone.
